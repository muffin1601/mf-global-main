## Backend effects and permission checks

Use the component and line in each row to trace a particular handler. Permissions below describe the common entry points. Individual actions may narrow them further. Navigation, locally edited fields, dialog cancellation and table display have no persisted effect until submission.

| Surface | Handler or service | Expected change or read | Authorization boundary |
|---|---|---|---|
| Lead form and list | crm/lead-management/actions.ts ? server/leads | View scoped leads. Creates write lead, initial status, assignments and activity records. Updates can add status and ownership history. | ADMIN or assigned USER. Reassignment and sensitive edits require administrator rights. |
| Activity and follow-up controls | crm/activities/actions.ts ? server/activities | Create or change activity state, timestamps and timeline. | Role grants plus ownership and lead access. |
| Import wizard | /api/lead-import/check, /jobs and /jobs/[id]/batch | Preview reads identities. Commit writes import job and row records and eligible leads. | Authenticated actor. Job actions scoped to owner or the implemented administrative grant. |
| Reporting and downloads | /api/reports/lead-insertion/export, /api/leads/export | Read filtered rows. CSV, XLSX and PDF responses depend on endpoint. | Server-side role and assignment scope. |
| Product and category controls | /api/products and /api/categories | Catalog, prices, category links and images. | Signed-in reads. Administration for catalog writes. |
| Quotation editor | crm/quotations/actions.ts and /api/quotations/[id]/pdf | Writes parent, items and counter transactionally. PDF reads persisted values. | Owner or administrator. Custom numbering series is administrative. |
| Vendor directory and profile | crm/vendors/actions.ts, /api/vendors | Vendor, contact, bank, document, status and audit records vary by operation. | Check the specific vendor capability. USER has view, create, edit, export and document grants. |
| Employee form | crm/user-management/actions.ts | User profile, enablement, audit and Supabase identity. | ADMIN. Hosted identity behavior remains a staging gate. |
| Saved views | crm/views-actions.ts | Persist or delete the actor's view configuration. | Signed-in owner. |
| Search, navigation and themes | /api/search, src/components/layout/app-shell.tsx | Read scoped search results, navigate, or store a browser preference. | Search runs with the actor's record scope. |
| Careers, contact and blog | See public and administrative registrations in API_INVENTORY.md | Job/application/blog data, storage and delivery effects depend on the form. | Public and administrative routes have distinct contracts. |

The per-control acceptance rows in TEST_MATRIX.md track the remaining verification. The browser artifact directory also contains per-viewport Chromium accessibility-tree extracts ending in `.controls.json`, with computed roles, accessible names and disabled state.
